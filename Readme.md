## 📌 프로젝트명: 공공 전자인계·인수 업무 시스템 운영 및 기능 개선

**기간:** 2025.07 ~ 재직중  
**성과:** 전국 3만 5천여 개 배출업체와 80여 개 처리업체가 이용하는 공공 법정 업무 시스템을 운영하고, 지사 실적보고 절차 개편 후 2개 분기 동안 관련 문의 0건 유지

### 🔧 주요 업무

- 전자인계·인수서 작성부터 제출·회수·마감·집계까지 전체 업무 기능 운영 및 개선
- 운영 DB와 HIST 데이터 분석을 통한 처리내역 추적 및 통계·집계 정합성 검증
- 지사 실적보고와 법정 처리기한 등 현업 업무 기준을 시스템 로직에 반영
- 배치·대외 연계·차량 운행정보 미들웨어 운영 및 장애 대응
- SI 기능 인수와 Oracle 19c 전환에 따른 애플리케이션 검증

### 🧑‍💻 역할

1. 2인 운영팀으로 시스템 전반의 유지보수·기능 개선·장애 대응 수행
2. 현업 요청에 따라 운영 데이터 집계 및 누락·불일치 원인 분석
3. JSP·DB 로직 수정과 폐수 비중 자동계산 등 반복·수기 업무 개선
4. SI 기능의 소스·데이터 정합성을 검증하고 발견된 오류 직접 수정
5. 장애 원인과 조치 내용을 현업·관련 업체에 공유하고 운영 반영

### 🛠️ 주요 사용 기술

- Java / JSP / eGovFramework
- MyBatis / Oracle DB
- Batch / 대외 연계
- JEUS / UNIX
- AIReport / AIDesigner / SVN

### 📈 성과

- 분기 중 상시 작성이 가능하도록 실적보고 로직을 개편하여 적용 후 2개 분기 동안 콜센터 관련 문의 0건
- 차량 운행 데이터 수신 프로그램의 DB 연결 설정을 보완하여 이후 2개월간 중단 없이 운영
- SI 신규 수탁량현황의 TEST 계정 제외 조건 누락을 발견·수정하여 전자인수서와 집계 정합성 확보
- 연간 100건 이상의 기능 개선·운영 데이터 분석·장애 대응 요청 수행

### 🧩 문제 해결 사례

- **분기 종료 후 짧은 작성기간으로 발생하던 실적보고 불편 개선**
  → 분기 중 상시 작성·임시저장이 가능하도록 제출·회수·마감·집계 로직을 개편하고, 적용 후 2개 분기 동안 관련 문의 0건 유지

- **차량 운행 데이터 수신 프로그램의 반복 중단 문제 해결**
  → 서비스 로그와 컴파일 산출물을 분석해 비정상 입력값·예외처리 누락·DB 연결 문제를 확인하고, 관련 업체에 원인을 전달한 뒤 연결 설정을 보완하여 2개월간 중단 없이 운영

- **시스템 오류 기준과 법정 작성기한 불일치 보완**
  → 대행처리 인계서의 시스템 오류 기준과 현업이 확인한 법정 3일 기준을 구분하도록 조회조건을 추가하여 실제 기한초과 대상 선별 지원

## 📌 프로젝트명: 열차운행정보 통합 관제 웹 구축

**기간:** 2024.05 ~ 2025.03  
**성과:** 12개 열차 프로젝트의 일 평균 약 1~2만 건 규모 LTE 중고장 분류 데이터를 통합하고, 정상 통신 환경에서 약 1초 이내 관제 화면 반영

### 🔧 주요 업무

- 프로젝트별로 분산된 열차 고장·운행 데이터를 중앙 WEBDB로 통합
- LTE 중고장 실시간 관제와 프로젝트·차량·기간별 검색 및 통계 화면 개발
- 운행정보 BLOB의 바이트·비트 정의를 구조체로 매핑하는 공통 파싱 라이브러리와 기관사 관제 화면 구현
- GPS·위치 데이터를 활용한 고장 발생 위치와 열차 현 위치 시각화

### 🧑‍💻 역할

1. WEBDB와 데이터 수집 프로그램부터 웹 화면까지 전체 관제 시스템 개발 전담
2. 프로젝트별로 상이한 DB·인터페이스를 분석하여 공통 데이터 구조로 매핑
3. 차량사업소 현장 시험에 참여하여 오류를 확인하고 사용자 피드백을 반영
4. 신규 프로젝트 추가 절차를 수립하고 관련 내용을 문서화

### 🛠️ 주요 사용 기술

- C# / .NET Core 3.1
- ASP.NET Core MVC / SignalR
- MSSQL / SQL Dependency / Service Broker
- JavaScript / jQuery / Leaflet.js
- IIS

### 📈 성과

- 고속철 3개·전동차 2개·일반차량처 7개 등 총 12개 프로젝트 데이터 통합
- 일 평균 약 1~2만 건의 차량 중고장 분류 데이터를 수집·관제
- 다수 차량의 중고장 동시 발생 시험에서 LTE 정상 통신 기준 약 1초 이내 화면 반영 확인
- BLOB 데이터 기반 기관사 관제 화면을 구현하고 실제 차량 시험 후 고속차량처 적용 완료
- 코레일 차량사업소 실사용자 만족도 조사에서 90% 이상 만족 응답

### 🧩 문제 해결 사례

- **프로젝트마다 다른 DB·인터페이스로 인한 데이터 통합 문제**
  → 프로젝트별 매핑 로직과 공통 WEBDB 구조를 설계하여 12개 프로젝트 통합

- **장시간 무수신 시 실시간 관제 연결이 종료되는 문제**
  → 주기적 연결 확인, 자동 재연결 및 누락 데이터 재조회로 관제 데이터 연속성 확보

- **바이너리 운행정보 화면 표시 오류 해결**
  → 실제 BLOB 데이터의 바이트 배열 차이를 확인하고, 프로토콜의 바이트·비트 정의를 구조체로 모델링한 공통 파싱 라이브러리에 데이터 묶음별 순서 변환을 적용하여 관제 화면 상태·수치값 정상 표시

## 📌 프로젝트명: 사내 통합 알림톡 발송 시스템 구축

**기간:** 2024.02 ~ 2024.04  
**성과:** 전사 건의사항에서 가장 많이 제기된 CS 업무 누락 문제를 해결하기 위해 사내 최초 통합 알림톡 시스템의 설계·개발을 전담하고, 일 평균 약 500건 처리

### 🔧 주요 업무

- ERP의 CS 요청 등록·진행·완료 및 마감임박 알림 자동화
- 공통 알림 테이블과 업무 유형별 비즈톡 템플릿 전송 구조 설계
- Service Broker·SQL Dependency 기반 실시간 데이터 변경 감지
- 관리자용 발송 이력 및 성공·실패 결과 조회 화면 개발
- CS 알림을 시작으로 PLC 설비·사내 카페 업무까지 적용 확대

### 🧑‍💻 역할

1. 현업 요구사항 협의부터 DB·전송 프로그램·조회 화면의 설계·개발까지 전담
2. 알림 대기·전송 중·완료·실패 상태 및 처리 결과 저장 구조 설계
3. C# WinForms 기반 상시 실행 프로그램과 비즈톡 API 연동
4. 중복 발송 방지, 실패 재시도 및 토큰 자동 갱신 등 예외 처리 구현
5. CS 전용 알림을 다른 사내 업무에 확대 적용하도록 제안·구현

### 🛠️ 주요 사용 기술

- C# / .NET 6.0
- Windows Forms
- MSSQL
- SQL Dependency / Service Broker
- Kakao BizTalk API
- Classic ASP / IIS

### 📈 성과

- CS 요청 상태와 알림 결과를 이력화하여 미확인·미회신에 따른 업무 누락 및 부서 간 책임 공방을 사실상 해소
- CS·PLC·카페 업무에 적용하여 일 평균 약 500건의 알림톡 처리
- 개발 완료 후 퇴사 시점까지 사내 공통 알림 시스템으로 지속 운영

### 🧩 문제 해결 사례

- 발송 직전 상태를 `전송 중`으로 변경하여 동일 데이터의 중복 발송 방지
- 전송 실패 시 최대 3회 재시도 후 별도 실패 테이블로 이관
- 토큰 만료 3시간 전 자동 갱신하고, 최종 실패 시 담당자 메일 알림

## 📌 프로젝트명: 사내 업무 시스템 개발 및 인트라넷 운영

**기간:** 2023.08 ~ 2025.05  
**성과:** 설비 관제, 사내 주문·정산, 데이터 수집 등 10여 개 이상의 업무 시스템과 자동화 기능을 개발하여 반복·수기 업무를 시스템화

### 🔧 주요 업무

- Classic ASP 기반 사내 인트라넷 유지보수 및 신규 기능 개발
- PLC 설비 상태 관제·카카오톡 알림 및 웹 원격 제어 기능 개발
- 사내 카페 주문·제조·완료 알림 및 월별 정산 시스템 개발
- 전력 시세(SMP) 자동 수집·조회·보고 프로그램 개발
- 계측기·공구·자재 및 정기점검 이력 관리 시스템 개발

### 🧑‍💻 역할

1. 현업 담당자와 직접 협의하여 요구사항 및 업무 흐름 분석
2. MSSQL 데이터 구조·쿼리와 Classic ASP 업무 화면 설계·구현
3. PLC 관제·제어 및 이상 발생 시 담당자 카카오톡 알림 기능 구현
4. 카페 주문부터 인사팀 정산까지 이어지는 업무 흐름 구현
5. C# 기반 SMP 수집·저장·조회·카카오톡 보고 자동화

### 🛠️ 주요 사용 기술

- Classic ASP / JavaScript
- C# / Windows Forms
- MSSQL / SQL Dependency
- IIS
- Kakao BizTalk API / PLC 연계

### 📈 성과

- PLC 설비 이상 자동 알림 및 웹 원격 제어 환경 구축
- 카페 주문·제조 알림과 직원별 월간 급여 정산 자료 생성 자동화
- SMP 데이터 새벽 3시 수집 및 오전 8시 30분 카카오톡 보고 자동화
- 계측기 정기점검 이력 시스템화 후 적용 기간 내 누락 0건 유지

### 🧩 문제 해결 사례

- 개발자별로 다르게 구현된 중복 로직·데이터 및 과도한 분기문 정리
- DB 폴링 방식을 SQL Dependency 기반 변경 감지 방식으로 전환
- User-Agent 변경으로 중단된 SMP 크롤링 로직 수정 및 자동 수집 복구
